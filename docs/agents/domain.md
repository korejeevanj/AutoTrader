# Domain docs: single-context

- Vocabulary lives in `GLOSSARY.md` at the repo root. Read it before naming things
  and use its terms exactly.
- Architecture decisions live in `docs/adr/` (create it on first ADR). Read relevant
  ADRs before changing a decided area, and record new hard-to-reverse decisions there.
- Binding project rules stay in `AGENTS.md`; this file only describes where domain
  knowledge lives.
- If a term or decision you need isn't documented, note the gap rather than inventing it.
